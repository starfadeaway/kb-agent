# LLM 降级链：换模型之前，先想清楚该不该换

## 问题

单基座 Chat 的可用性完全押在一个供应商上。429、5xx、超时、连接中断，
任何一种出现，用户看到的就是一次 500。

直觉反应是"捕获异常 → 重试 → 换个模型"。这句话里藏着两个会静默出错的点。

## 一、不是所有失败都值得换供应商

按「同样的请求再发一次，结果会不会变」判断：

| 类别 | 例子 | 换供应商有用吗 |
|---|---|---|
| **可重试** | 429 限流、5xx、连接超时、连接中断 | 有 —— 这是环境/配额问题，换家可能就绕过去了 |
| **不可重试** | 400 参数错、401 密钥无效、403、404 模型名不存在、内容过滤 | **没有** —— 同样的请求换谁都一样 |
| **本地错误** | `ValueError`（未配置密钥、未知基座名）、`TypeError`、`KeyError` | **没有** —— 这是代码问题，重试三遍只是把同一个 bug 触发三次 |

对不可重试的故障做降级，实际后果是：一次 200ms 的失败被拉成
N 倍延迟 + 一份多余的 token，而真正的错误信息被重试噪声淹没。
**降级链最危险的用法，是它把一个清晰的报错变成了一个模糊的超时。**

分类逻辑在 `backend/app/llm/fallback.py`。两条硬约束：

1. 不可重试的类型**枚举**出来（`_FATAL`），不写"其余都算可重试" ——
   新增一个 SDK 异常类型时，默认必须落在安全的一侧。
2. **未知异常默认 fatal**。宁可漏降级，也不要把 `ValueError` 拿去重试三遍。

## 二、降级必须显形

这是比第一条更要紧的一条。

一次悄悄的降级意味着：**用户拿到的答案其实是另一个模型生成的，
而系统没有任何地方记录这件事**。演示里看不出来，
但在本项目里这是致命的 —— 跨模型对比实验（实验 D / 实验 E）
会把"模型换了"这个隐藏变量混进质量分里，
而实验 D 刚刚因为检验对象用错推翻了结论。同一个坑不能踩第二次。

所以降级事实被强制带回三层：

| 层 | 字段 |
|---|---|
| 单次调用 | `chat()` 返回值新增 `fallback: {"used", "from", "to", "why"}` |
| 实例留痕 | `LLMClient.fallback_stats()` → `total` / `by_pair` / `recent` |
| 健康检查 | `GET /api/health` 的 `fallback` 段 |

`why` 里记的是故障分类（`retryable/RateLimitError/status=429`），
不含请求体、不含密钥。

## 配置

```dotenv
# 逗号分隔；留空 = 不降级（默认，不改变现有行为）
CHAT_FALLBACKS=minimax
# 第 n 次降级前等待 n × 该值秒
CHAT_FALLBACK_BACKOFF=0.8
```

链的构造规则（`LLMClient._fallback_chain`）：

- `[主基座] + CHAT_FALLBACKS`，去掉与主基座重复的，按出现顺序去重
- **显式传了 `model` 时完全不降级** —— 实验脚本指定模型时的诉求是
  "就用这个模型"，悄悄换一个等于把实验变量换掉

## 已知边界（说清楚比装完整重要）

- **主基座不重试**。当前实现是「主基座失败 → 直接换下一个」，
  没有做同基座的短暂退避重试。连续两次瞬时抖动会直接触发降级。
  这是刻意的简单化：同基座重试会进一步拉长尾延迟，
  而这个系统本来就有 `AGENT_WALL_TIMEOUT=60s` 在兜着。
  真要做，应该单独测「重试 vs 直接降级」的延迟分布再决定。
- **降级不保证质量等价**。DeepSeek 与 MiniMax 的实测差异见实验 E：
  质量打平（p=0.1667 未达显著），但延迟差 4.08 倍（p=0.0011 显著）。
  也就是说降级会**显著改变延迟特征**，但不会明显改变答案质量。
  这个结论来自 n=14 的配对检验，样本小，只能当方向性判断。
- **不做 embedding / rerank / judge 的降级**。只有 Chat 基座有第二条路；
  其余三个都只有 SiliconFlow 一个上游，降级无从谈起。
- **`fallback` 字段不参与 Judge 打分**。它不是质量维度。

## 守卫测试

`backend/tests/test_llm_fallback_chain.py`，30 项，覆盖：

- 分类：7 类瞬时故障可重试、6 类确定性/本地故障不可重试、未知异常默认不重试
- 链构造：去重、跳过主基座、空链、显式 model 时禁用降级
- 行为：429 触发降级、400/401 不触发、链长有界、成功路径不误标
- 留痕：`fallback_stats` 计数与配对、`/api/health` 透出
- 契约：`chat()` 返回值只增不减字段（实验脚本按 dict 取值）

双向验证：退回没有降级链的 `client.py` 实跑，**10 项失败**，
其中 3 项是行为断言而非属性缺失 ——
429 直接抛出未降级、返回值无 `fallback` 字段、链只走了一格。
